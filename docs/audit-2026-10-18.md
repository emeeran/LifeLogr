# LifeLogr — Improvement & Enhancement Audit

**Date:** 2026-10-18 · **Scope:** full codebase (backend 105 files ≈ 17.6k LOC, frontend ≈ 23k LOC, desktop shell, packaging) · **Baseline:** `main` @ `8ae7193` (branch `fix/audit-phase1-data-loss`)

Four parallel review tracks — backend correctness, security/privacy, frontend quality, and testing/data-layer/packaging — produced ~110 findings. This report consolidates, deduplicates, and ranks them, with a resolution for each and a phased remediation roadmap.

---

## Executive summary

LifeLogr is a well-built app: strong backup/restore engineering (atomic swaps, tar-traversal guards, retention), correct AES-256-GCM usage, sanitized frontend markdown, loopback-by-default binding, and disciplined async hygiene in most services. **But the audit found one critical XSS chain, one RCE amplifier, three critical packaging bugs that make Docker unusable, and five data-loss bugs** — several in exactly the areas the app's privacy and durability promises depend on.

| Severity | Count | Highlights |
|---|---|---|
| Critical | 4 | Stored XSS in HTML exports · unscoped Tauri shell/fs (webview → host RCE) · broken Docker DB mount · nonexistent pip extra breaks image build |
| High | 14 | Unauthenticated API (DNS-rebinding reads) · TTS egress hidden from privacy report · 4 silent-data-loss bugs in editors/exports · stale-WAL restore hazard · tag-filter row duplication · import drops all tags |
| Medium | ~40 | Event-loop blocking on exports/crypto/media · memory unboundedness · missing FK indexes · silent error handling · editor mega-components |
| Low | ~35 | Dead code, status-code nits, a11y, config validation, i18n |

**Theme:** the codebase's two biggest systemic gaps are (1) *heavy CPU/file work on the async event loop* (exports, PIL, scrypt, copytree — freezes the whole API when the journal is large) and (2) *silent error swallowing* (store errors written but never rendered; failed saves look successful; failed imports skip entries without saying why). Both have cheap, pattern-consistent fixes because the codebase already contains the correct patterns to copy.

## Part 1 — Critical (fix now)

### SEC-C1 · Stored XSS in HTML exports → full journal theft
- **Where:** `backend/app/services/export_service.py:78` (`MarkdownIt()` default preset has `html=True`; `<script>` passes through verbatim), `:108-126` (unescaped `title`/`mood`/tag interpolation); `backend/app/services/notes_export_service.py:33,153-156`; served as inline `HTMLResponse` in `routers/export.py:18-26`, `routers/notes.py:426-430`.
- **Issue/impact:** any entry/note body — including content imported from a third-party Diarium/Day One ZIP — executes script when the exported HTML is opened. The export contains the whole plaintext journal; served from the API origin it is same-origin with the unauthenticated API and the CSRF guard explicitly trusts that origin → full read/write/delete of the journal.
- **Resolution:** construct renderers with raw HTML off (`MarkdownIt("commonmark", {"html": False})`, verify in both services); `html.escape()` title/mood/tag interpolations; serve with `Content-Disposition: attachment` + `Content-Security-Policy: sandbox` / `default-src 'none'`.

### SEC-H1 · Tauri capabilities unscoped: arbitrary process execution & file I/O from the webview
- **Where:** `desktop/src-tauri/capabilities/default.json:7-10` (`shell:allow-execute`, `shell:allow-spawn`, `shell:allow-stdin-write`, `shell:allow-open`), `:20-21` (`fs:allow-read-file`, `fs:allow-write-file`) — ACL manifest confirms these grant commands "without any pre-configured scope".
- **Impact:** any webview compromise (e.g. via SEC-C1) becomes host RCE / arbitrary file theft — the worst possible amplifier for a privacy-first app. The scoped sidecar entry at `:12-17` is fine; the generic permissions defeat it.
- **Resolution:** delete the generic shell permissions (keep the scoped sidecar spawn); scope fs writes to dialog-driven paths (`$DOWNLOAD/**`); restrict `shell:allow-open` to `https://*`, `mailto:`, `tel:`. Related: `desktop/src-tauri/src/main.rs:417-421` auto-allows *every* webview permission request (camera/geolocation) — allow only microphone `MediaStream` from the app origin.

### PKG-C1 · Docker DB volume mount is broken — container can never start against its DB
- **Where:** `docker-compose.yml:12` mounts host dir `./data` onto the SQLite *file* path (`/app/backend/prod.db`).
- **Impact:** SQLite can't open a directory → crash-loop (`restart: unless-stopped`).
- **Resolution:** mount `./data:/app/backend/data`, set `DATA_DIR=/app/backend/data`, drop the `DATABASE_URL` override so `config.py` derives it.

### PKG-C2 · Docker media volume silently unused + nonexistent pip extra breaks the build
- **Where:** `Dockerfile:31,36` — `MEDIA_DIR` is never set, so media lands in the XDG default under `/root` and the `./media` mount is dead (media lost on container replacement). `Dockerfile:19` — `--extra pdf` doesn't exist in `pyproject.toml` (extras: `ocr/tts/image/all`) → build fails or silently skips intent. `docker-compose.yml:14-15` — mandatory `env_file: backend/.env` (gitignored) fails fresh clones; `APP_ENV=production` + default `SECRET_KEY` fails validation at boot; no healthchecks despite `/health` (`main.py:378`).
- **Resolution:** `ENV DATA_DIR=/app/backend/data`; install with `--extra all` from `uv.lock` for reproducibility; make `.env` optional with sane defaults; add `HEALTHCHECK` and compose healthchecks.

## Part 2 — High severity

### Security & privacy

**SEC-H2 · Unauthenticated API with no Host validation → DNS-rebinding reads of the entire journal.** The CSRF guard (`main.py:253-285`) covers mutating methods only; GETs from a rebound `attacker.com → 127.0.0.1` can read everything, including `/backup/export` (full tar.gz). The guard also accepts any port on localhost, so any local process can mutate via the browser. *Resolution:* per-launch random bearer token (generated at sidecar start, passed to the webview via Tauri, required on every `/api` request, `/health` exempt) and/or validate `Host` ∈ {`127.0.0.1:port`, `localhost:port`, `tauri.localhost`}. This single change retires most of the loopback attack surface.

**SEC-H3 · Read-aloud sends the journal to Microsoft — missing from the egress report.** `routers/tts.py:184-199` streams entry text to Edge TTS (cloud), but `/system/egress-report` (`routers/system.py:42-115`) enumerates only `cloud_ai`, `cloud_backup`, `web_clip`, `ocr`, `embeddings`, and `PrivacyTab.vue:37` claims those are "the **only** surfaces" that send data off-device. The headline privacy promise is factually broken. *Resolution:* add a `read_aloud` surface to the report; offer an offline TTS engine (Piper/espeak) as the default.

### Data loss & correctness

**DATA-H1 · Stale WAL sidecars can survive a restore and resurrect pre-restore data.** `core/restore.py:162-231` replaces the main DB file but never unlinks `{db}-wal`/`-shm`; `_checkpoint_live` is explicitly best-effort. The codebase already knows the fix — boot-snapshot recovery does exactly this cleanup (`database.py:315-318`). *Resolution:* unlink both sidecars after the atomic write. Related (DATA-H2): backups bundle WAL/SHM precisely because the main file may lag (`archive.py:63-68`), yet all three restore paths read only the main file — a backup taken during WAL activity restores to an older state silently. Either checkpoint-only backups or replay sidecars on restore.

**DATA-H3 · Cloud restore reports failure after succeeding (and vice versa).** `atomic_restore` reinitializes the engine (`restore.py:200-206`) while `backup_service.py:476-503` keeps using the request's old-engine session for `count_all()` → `PendingRollbackError` → misleading 409 "Restore failed" despite success. Every restore failure is also mapped to `ConflictError` → 409 regardless of cause. *Resolution:* after `atomic_restore`, open a fresh session for counts; map error classes to 400/502 with `raise ... from e`.

**BCK-H1 · Exports silently lose entries to filename collisions.** Markdown export writes `entries/{entry_date}.md` (`routers/entries.py:205`) and `journal/{Y}/{M}/{date}.md` (`export_service.py:302-305`); notes use title-only slugs (`notes_export_service.py:98-102`). Multiple entries per day or same-titled notes overwrite each other inside the zip. *Resolution:* include entry id (`2026-05-01-123.md`); dedupe slugs.

**FE-H1 · Unsaved note edits silently lost on navigation.** `NoteEditor.vue` exposes `isDirty` (`:908`) but nothing consumes it; no `onBeforeRouteLeave` exists in the codebase; notes autosave is intentionally off. Clicking a sidebar item discards dirty edits with no prompt. *Resolution:* router-level guard consulting a shared dirty flag, wired the way `EntryEditor.vue:311-314` already does for `ui.editorIsDirty`.

**FE-H2 · Silent save failures.** `stores/notes.ts` writes `error.value` on every failure but zero components render it ("store surfaces error" comments at `NoteEditor.vue:229-231` etc. are false). With autosave off, a failed Ctrl+S looks saved. *Resolution:* global toast fed by store errors; stop the swallow-and-comment pattern.

**BCK-H2 · Backend tag filter duplicates rows and inflates totals.** `entry_service.py:352-353` inner-joins `EntryTag` without `distinct()` — an entry with two of the requested tags appears twice and is double-counted, breaking pagination. The notes variant already uses the correct subquery form (`note_service.py:317-318`) — the asymmetry is itself a smell. *Resolution:* 2-line change to the subquery form.

**BCK-H3 · `/entries/import` silently drops all imported tags and coordinates.** `routers/entries.py:644-666` builds `tag_ids` (and importers emit `latitude`/`longitude`, e.g. `importers/dayone.py:60-61`), but `EntryService.create` (`entry_service.py:56-79`) never reads `tag_ids`, and `EntryCreate` has no geo fields. Same dead-schema issue for notes (`schemas/note.py:52,81`). *Resolution:* honour `tag_ids` in create/update and add geo fields — or strip the dead schema and stop building it.

## Part 3 — Medium severity (grouped by theme)

### M-A · Event-loop blocking (the biggest systemic issue)
Heavy CPU/file work runs directly in async paths; with a multi-thousand-entry journal one request freezes the entire API (health checks, saves) for seconds to minutes:

| Location | Work |
|---|---|
| `routers/entries.py:157-330`, `export_service.py:128-451` | full-table loads, sync zip/pdf/sqlite-build for exports |
| `services/media_service.py:185-233`, `note_media_service.py:104-113`, `video_service.py:54-56` | PIL decode/resize/encode of up to 25 MB; sync `read_bytes`/`write_bytes` |
| `services/encryption_service.py:52-66` | PBKDF2 600k iters / scrypt N=2^15 per call (~0.1–0.5 s) |
| `services/storage_service.py:160-172` | `shutil.copytree` of the whole media tree during hot storage relocation |
| `routers/video_notes.py:48-58` | whole video read into RAM as one `Response` (breaks Range/seeking; sibling endpoint in `media.py:162-178` already does it right) |
| `routers/tts.py:206-228`, `settings_service.py:73-100` | sync `glob`/`stat` eviction walks; recursive `dir_size` on every `GET /settings` |

**Resolution:** one pass wrapping these in `asyncio.to_thread` — the codebase already has the pattern in three places (`routers/backup.py:178-182`, `restore.py`, `storage_service.py:139`) to copy. Use `FileResponse` for video; cache dir-size.

### M-B · Memory unboundedness
- **Imports/uploads buffered whole:** `/entries/import` (`entries.py:543,547`) and media uploads (`media.py:36,72`) `await file.read()` with no cap — decompression bombs/OOM on an unauthenticated service; `/backup/import` already has the correct streamed spool + 2 GiB cap (`backup.py:207-230`) — reuse it.
- **Cloud restore buffers whole archives in RAM** (`backup_service.py:404-447`), contradicting the backup path that was explicitly rewritten to stream. Drive first-upload also buffers (`cloud_sync_service.py:491`). *Fix:* stream downloads to temp files; Drive resumable upload.
- **Undo history holds full body copies** (`useEditorHistory.ts:16-36`, cap 200 × full strings — ~200 MB for a 1 MB note). *Fix:* patch-based history (`noteEditorDiff.ts` already exists) or byte-budget cap.

### M-C · Search & embeddings integrity
- **Mixed-dimension vectors 500 all semantic search** after a model swap (`semantic_cache.py:64`; `model_name` persisted but never checked) and encrypted entries keep plaintext-derived vectors — "encrypted" content remains similarity-searchable (`search_service.py:296-310`). Entries saved while Ollama is down get no embedding and no backfill (`enrichment_service.py:41-44`). *Fix:* filter embeddings by `model_name`; delete embeddings on encrypt; backfill sweep.
- **Hybrid search wrong `total`** — sub-searches hard-capped at 100; `total = len(merged)` (`search_service.py:339-403`). Deep pages silently empty. *Fix:* propagate sub-totals or document the ceiling.
- **FTS drift healing is count-only and asymmetric** — content drift with correct counts never heals; `notes_fts` has no `user_version`-tracked rebuild (only entries do, `database.py:660`). *Fix:* extend version tracking; compare ID sets. Also: boot DDL DROP/re-CREATEs all 12 FTS triggers in every process on every start (`database.py:766-1026`) — concurrent sidecar + web-deb start can race; gate on the version stamp.
- **Vector cache torn reads** — mutators bypass `self._lock` while `search()` reads (`semantic_cache.py:109-176`). *Fix:* publish via single tuple swap under lock.
- **300 s Ollama timeout on `embed()`** on every hybrid search (`ollama_service.py:311-330`) — a hung Ollama stalls all searches 5 min. *Fix:* short dedicated timeout + single-flight guard.

### M-D · Missing indexes & query inefficiency
No indexes on `media.entry_id`, `voice_recordings.entry_id/media_id`, `video_notes.entry_id`, `note_media.note_id`, `entry_prompts.entry_id`, `backup_snapshots.config_id` (`_INDEX_MIGRATIONS` covers only the tag joins) — full scans per page load as media grows. Plus: N+1 in the tags API (2N+1 queries, `routers/tags.py:18-51`); `GET /notes/folders` eager-loads every note body via model-level `lazy="selectin"` (`models/note.py:56-58`); duplicate detection loads every entry body (`entries.py:621-623`). *Fix:* add indexes + `_INDEX_MIGRATIONS` entries (bump `_SCHEMA_VERSION`); grouped queries; drop the unused selectin.

### M-E · Silent failures & wrong status codes
- `encrypt` route misses the already-encrypted `ValueError` → 500 instead of 409 (`encryption.py:26-37`).
- `POST /backup/run` declares 202 "background" but runs synchronously (`backup.py:59-66`); failures surface as generic 500.
- `sync.py:126-127` — unsupported provider escapes as 500, should be 400.
- Frontend: `TimelineView.load()` / `MediaTimelineView` / `search()` have try/finally with no catch → unhandled rejections, no error UI; `BackupTab.createConfig` unguarded; blind 6 s `setTimeout` refetches not cleared on unmount; five stores have no error state at all.
- Import endpoints swallow per-entry errors (`skipped += 1`) with no reason returned to the client; notes variant doesn't even log.
- *Fix:* uniform store `{loading, error}` contract + typed `ApiError {status, detail}` parsed once in `api/client.ts` (which currently throws raw transport strings that components `alert()` verbatim, and `AITab.vue:57-69` regex-parses back out).

### M-F · Crypto & secrets hardening
- **Legacy unsalted KDF still used for "encrypt selection"** (`encryption.py:116,126` → `salt=None` deterministic path) — same passphrase+text → identical ciphertext; precomputed-dictionary friendly. *Fix:* per-item salt via the v2 scrypt path; offer one-click legacy re-encryption.
- **Decryption persists plaintext to disk permanently** (`encryption_service.py:127-145,182-194`); titles always plaintext (documented). At-rest only. *Fix:* memory-only unlocked session cache; document limits.
- **Default `SECRET_KEY` only warns** — credentials encrypted under a public constant on dev/bare runs (`security.py:28`, warn at `main.py:56-61`). *Fix:* hard-fail `encrypt()` when the default key is in use.
- Missing PKCE on all four OAuth flows (low loopback impact, cheap, increasingly provider-mandated).
- `ollama_base_url` accepts any http(s) host (`settings.py:120-128`) — one unauthenticated `PUT /settings` redirects all journal-content AI egress to an arbitrary host. Apply the web-clip SSRF guard's internal-address check.
- `upload_from_path` denylist (only `~/.ssh`, `~/.gnupg`, `~/.config`) lets an unauthenticated request re-serve almost anything under `$HOME` (`media_service.py:165-177`). *Fix:* positive allowlist or Tauri-issued one-time token.
- `.secret_key` sits next to the DB it decrypts (`config.py:104-149`) — correct implementation (0600, `token_hex`), but keyring (libsecret) would be strictly better; document the threat model.

### M-G · Frontend architecture
- **Editor mega-components**: `NoteEditor.vue` (1,685 lines) and `EntryEditor.vue` (1,531) copy-paste OCR, media-embed, path-drop, paste-to-table, resize wiring, and toast CSS; NoteEditor even inlines a 60-entry emoji array while a shared `EmojiPicker.vue` exists. *Fix:* extract `useEditorMedia`/`useEditorOcr` composables — shrinks each editor ~400 lines.
- **Router vs `ui.activeView` dual source of truth** — sidebar navigates both; Timeline/Media/search jump views without the router; center pane renders the route while AppShell gates panels on the flag → "editor opens over Timeline", Back/Forward desync, wrong startup highlight. *Fix:* derive `activeView` from the route or one `navigate(view)` helper.
- **Media URL breaks desktop playback** — `EntryDetail.vue:57` builds a relative `/api/v1/media/...` URL with no `API_ORIGIN`; fails under `tauri://`. One-line fix using the pattern already in `useRecordings.ts:205`.
- **EntryEditor click-listener leak** — `removeEventListener` passes a different arrow function than `addEventListener` (`EntryEditor.vue:488-517`), so removal is a no-op; a closure-holding listener accumulates per mount. Hoist to a named function.
- **Notes list capped at hardcoded 100** (`NotesView.vue`, five call sites) — note 101+ unreachable from the tree.
- **Calendar refetches the whole month on every mutation** (watches `entries.lastUpdated`); **per-keystroke full-body work** in NoteEditor (3 regex passes + full-string hash per input even when TTS idle); **`loadEntry` race** (no sequencing token); **failed save still switches entry** (`AppShell.vue:109-114`).
- Toast/confirm logic implemented 3 ways + 48 native `alert()/confirm()/prompt()` call sites (they block the Tauri webview thread and are unstyleable); a `ConfirmDialog.vue` exists, unused.
- **a11y:** 11 `aria-label`s vs ~158 `title=`s; notes tree is divs with no `role="tree"`/keyboard support; modals lack `role="dialog"`/focus trap; icon-only buttons invisible to AT.

### M-H · Cloud backup & scheduler
- **Cloud retention not enforced** — local backups are pruned; cloud ones grow unbounded (`backup_service.py:145-284`). *Fix:* prune `lifelogr-backup-*` beyond a configurable count after upload.
- Provider dispatch copy-pasted 5× (`backup_service.py` ×4 + `sync.py:68-127`, with visible drift — sync's refresh path doesn't upgrade v1 tokens). *Fix:* centralize on the existing `_cloud_provider_for`.
- `POST /backup/run` check-then-insert for "already in progress" isn't atomic across processes — no unique constraint on open snapshots.
- TTS lock map grows forever; entry TTS ignores `is_deleted`/`is_encrypted` — deleted entries are spoken, encrypted entries read base64 ciphertext aloud (`tts.py:60-176,292-297,381-386`).

## Part 5 — Testing & coverage posture

**Backend: strong but concentrated** — 45 files ≈ 7,200 lines, 62% floor; excellent backup/restore, scheduler, boot-snapshot, PRAGMA coverage. **Gaps that matter most:**
1. **The FTS trigger sync path is never tested** — `conftest.py:18-21` creates FTS tables *without triggers*, so every search test exercises the ILIKE fallback.
2. **Schema upgrade has zero coverage** — no fixture boots an old DB through `init_db`; `_drop_removed_feature_tables` unconditionally DROPs a hardcoded list on every boot, so a regression destroys user data on upgrade rather than failing. (No Alembic anywhere; `_SCHEMA_VERSION = 1` is write-only.)
3. Untested services: `enrichment_service` (whole embedding pipeline), `hashtag`, `note_media_service`, `settings_service`, `template_service`.
4. Untested HTTP surface: `box`, `dropbox`, `onedrive`, `video_notes` routers.

**Frontend: thin** — 5 vitest files for 56 TS modules + 63 components; no store or `api/client.ts` tests; 3 Chromium-only e2e specs; **no ESLint/Prettier at all** (only `vue-tsc` + build).

**CI asymmetry** — Makefile runs backend pytest/ruff/mypy only, despite CI running the full frontend matrix.

## Part 6 — Remediation roadmap

### Phase 1 — Critical security & packaging (≈1–2 days)
1. SEC-C1 export XSS (renderer option + escaping + attachment/CSP headers)
2. SEC-H1 Tauri capability scoping + permission-request tightening
3. PKG-C1/C2 Docker fixes (DATA_DIR, extras, `.env`, healthchecks)
4. SEC-H3 add `read_aloud` to the egress report (one entry — honest privacy docs immediately)

### Phase 2 — Data loss & correctness (≈2–3 days)
5. DATA-H1 restore WAL-sidecar cleanup (+ backup/restore sidecar policy)
6. DATA-H3 post-restore session hygiene + error-class status mapping
7. BCK-H1 unique export filenames
8. BCK-H2 tag-filter subquery
9. BCK-H3 honour `tag_ids`/geo on import (or strip dead schema)
10. FE-H1/H2 shared dirty flag + router guard + global error toasts; FE media-URL fix; listener-leak fix

### Phase 3 — Event-loop & memory pass (≈2–3 days)
11. `asyncio.to_thread` sweep (M-A table) + `FileResponse` for video
12. Streamed spool + caps for imports/uploads (reuse `backup.py` pattern); stream cloud restore
13. Missing FK indexes + `_INDEX_MIGRATIONS`; tags N+1; folders selectin
14. TTS/embedding timeouts, vector-cache locking, task-reference fixes

### Phase 4 — Trust & hardening (≈3–5 days)
15. SEC-H2 per-launch API token + Host validation
16. Crypto cleanups (M-F): v2 KDF for selection encryption, default-SECRET hard-fail, PKCE, SSRF guard on `ollama_base_url`, upload-path allowlist
17. `/backup/import` confirm + restore summary; cloud retention pruning

### Phase 5 — Frontend architecture & tests (ongoing)
18. Router/`activeView` unification; extract `useEditorMedia`/`useEditorOcr`; typed `ApiError` + store error contract; single toast/confirm service
19. Test investments in ROI order: FTS-trigger fixture → legacy-DB upgrade fixture → enrichment lifecycle → untested cloud routers → frontend store/client vitest; add ESLint + Makefile frontend targets

## What's already good (keep and protect)

- **Backup/restore engineering** — validated extracted DBs, atomic swap + media rollback, tar traversal/symlink/device rejection, retention, boot-snapshot recovery — the best-tested subsystem in the repo.
- **Crypto fundamentals** — 12-byte random GCM nonces, scrypt N=2^15 with per-item salts, versioned KDF migration; no secrets in logs.
- **SQL injection posture** — bound params everywhere, expanding bindparams, hardcoded table literals.
- **Frontend markdown** — every `v-html` pairs `marked` with DOMPurify; strict TS with zero `@ts-ignore`; virtualized lists where they matter; a genuinely well-factored editing core (`useRichTextEditor.ts`).
- **Egress discipline** — per-hop SSRF validation with DNS-rebinding checks on web clip; loopback-by-default binding with production refusal of non-loopback binds.

regressions the first implementation pass had introduced, then swept the tree
for the same classes:
